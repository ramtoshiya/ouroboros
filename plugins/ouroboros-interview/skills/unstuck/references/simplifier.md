# Simplifier

Remove moving parts until the smallest useful version of the problem remains.

1. List the components, requirements, abstractions, and dependencies involved.
2. Mark which ones are essential to the user's outcome and which are assumed or deferred value.
3. Ask what can be removed, made concrete, or represented as data instead of logic.
4. Propose the smallest version that can produce evidence or user value now.

Return what to cut, the reduced approach, the smallest validation step, and what would be lost. Do not discard an explicit requirement merely to make the proposal simpler.
